# Interview Copilot

Мультиагентный помощник интервьюера: превращает расшифровку технического
собеседования и утверждённую рубрику роли в структурированную карточку
кандидата, где у каждого вывода есть основание (ссылка на эпизод), а спорные
интерпретации помечены явно.

Главное отличие от обычного суммаризатора — **проверка обоснованности оценок**:
система отделяет рассказанный опыт от продемонстрированного, учитывает подсказки
интервьюера, помечает пробелы (отсутствие темы ≠ низкая оценка) и проверяет,
не шире ли вывод, чем подтверждают эпизоды.

## Архитектура

```
 Видео/Аудио ──(OpenRouter STT)──► Расшифровка ─┐
 Текст расшифровки ─────────────────────────────┤
 Рубрика роли ──────────────────────────────────┤
                                                 ▼
                 ┌─────────────── Оркестратор ───────────────┐
                 │  независимо и параллельно:                │
                 │   • Аналитик компетенций                  │
                 │   • Аналитик интервью                     │
                 │                                            │
                 │  затем:                                    │
                 │   • Ревизор оснований ── запрос повтора ──►│ (до N итераций)
                 └────────────────────┬───────────────────────┘
                                      ▼
                     Синтез карточки (детерминированный)
            ┌──────────────┬──────────────┬───────────────────┐
            ▼              ▼              ▼                   ▼
     Внутренняя     Версия для      Вопросы для         Эвалюация vs
      карточка      кандидата     следующего этапа    один LLM-вызов
```

- **Backend** — FastAPI (Python 3.12), SQLAlchemy async, Postgres.
- **Frontend** — React + Vite + Tailwind, отдаётся nginx.
- **LLM** — любой OpenAI-совместимый провайдер через OpenRouter; модель выбирается
  через `.env`. Для офлайн-работы есть детерминированный `mock`-провайдер.
- **Транскрибация** — OpenRouter STT (`/audio/transcriptions`, `verbose_json`
  с таймкодами и диаризацией); видео конвертируется через `ffmpeg`.

Три агента, инструменты (поиск по расшифровке, контекст эпизода, рубрика) и
детерминированный синтез карточки описаны в `backend/app/agents` и
`backend/app/services`.

## Быстрый старт

```bash
cp .env.example .env
docker compose up --build
```

- Фронтенд: http://localhost:8080
- API и Swagger: http://localhost:8000/docs

По умолчанию `.env` настроен на `mock` — всё работает **без ключа** на встроенном
демо-интервью. Чтобы включить реальную модель, заполните ключ и смените провайдеры
(ниже).

## Ключи и переменные окружения

Все переменные лежат в `.env` в корне репозитория (его читает docker compose).

| Переменная | Назначение |
|---|---|
| `OPENROUTER_API_KEY` | Ключ OpenRouter. Создать: https://openrouter.ai/keys |
| `LLM_PROVIDER` | `openrouter` для реальной модели или `mock` для офлайна |
| `LLM_MODEL` | id модели для агентов. Выбрать DeepSeek V4 на https://openrouter.ai/models и вписать его slug (например `deepseek/deepseek-v3.2` — замените на актуальный slug DeepSeek V4) |
| `TRANSCRIBE_PROVIDER` | `openrouter` или `mock` |
| `TRANSCRIBE_MODEL` | модель распознавания речи, например `openai/whisper-large-v3` |
| `MAX_UPLOAD_MB` | лимит размера загружаемого файла |
| `MAX_REVIEW_ITERATIONS` | сколько раз ревизор может запросить повторный разбор |

Чтобы перейти на реальную модель:

```
OPENROUTER_API_KEY=sk-or-ваш-ключ
LLM_PROVIDER=openrouter
LLM_MODEL=deepseek/<актуальный-slug-deepseek-v4>
TRANSCRIBE_PROVIDER=openrouter
```

Транскрибация и анализ используют один и тот же ключ. Если ключ пуст, система
автоматически работает в режиме `mock`, даже если провайдер указан как
`openrouter`.

## Демо-сценарий (для защиты)

Нажмите «Загрузить демо» — подставятся рубрика middle ML-инженера (5 компетенций)
и интервью с тремя специально заложенными ситуациями:

1. **Подсказка.** Reranking кандидат предложил только после прямой подсказки —
   компетенция «Проектирование решения» помечается как частично подтверждённая,
   ход решения — «после подсказки», а не как самостоятельный выбор.
2. **Непроверенная компетенция.** «Эксплуатацию и инциденты» не обсуждали —
   статус «Данных нет», а не низкая оценка.
3. **Слишком широкий вывод.** Реплику интервьюера «по system design кандидат
   слабый» ревизор помечает как недостаточно обоснованную.

Вкладка «Сравнение» прогоняет те же данные через один сильный LLM-вызов и
показывает, сколько неподтверждённых выводов и потерянных оговорок даёт каждый
подход.

## Загрузка видео/аудио

На шаге «Интервью» выберите «Видео / аудио», перетащите файл — он уйдёт на
транскрибацию, вернётся расшифровка с таймкодами, её можно отредактировать и
пустить в анализ. Ограничения STT: до 25 МБ на запрос у провайдера, длинные
записи стоит резать на части.

## Экспорт

На карточке — кнопки «Скачать .docx» и «Скачать .md» (внутренняя карточка,
версия для кандидата и вопросы следующего этапа).

## Локальная разработка

Backend:

```bash
cd backend
python3.12 -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
pytest
uvicorn app.main:app --reload
```

Тесты используют SQLite и `mock`-провайдер, поэтому проходят без ключа и без
Postgres.

Frontend:

```bash
cd frontend
npm install
npm run dev
```

Vite проксирует `/api` на `http://localhost:8000`.

## Структура

```
backend/app
  agents/        три агента + оркестратор + промпты
  llm/           провайдер-абстракция (OpenRouter + mock) и инструменты
  transcribe/    STT (OpenRouter + mock), ffmpeg, форматирование
  services/      расшифровка, синтез карточки, эвристики, эвалюация, экспорт
  api/routes/    REST-эндпоинты
  db/            модели и сессия
  repositories/  доступ к данным
  seed/          демо-рубрика и демо-интервью
frontend/src     React-приложение
```

Схема БД создаётся автоматически при старте backend.
